# ⚙️ 비동기 워커 · 스케줄러 · 무상태

worker-server가 담당하는 비동기 처리 계층. **"응답은 즉시, 처리는 뒤에서"** 패턴으로 사용자 체감 지연을 없애고, 무거운/주기적 작업을 API 서버와 분리했다.

## 낙관적 업데이트 + 큐잉
사용자 반응이 많은 작업(게시글 좋아요·조회수 등)의 사후 처리 — DB 반영, 실시간 랭킹 갱신, 알림 — 를 **라우터에서 직접 하지 않는다.** 라우터는 **큐에 작업만 넣고 즉시 응답**하고(클라이언트는 낙관적 업데이트), 실제 처리는 worker가 백그라운드에서 소비한다. 예약·메시지처럼 알림이 필요한 경로도 같은 패턴.

- **중요도 기반 재시도** — 큐 작업마다 중요도를 평가해 재시도 정책을 달리했다. *좋아요 알림*은 트래픽은 많고 중요도는 낮아 재시도를 최소화, *예약 발생·취소 알림*은 중요도가 높아 재시도(+백오프)를 보강.

## 무상태 & 분산 락
- 모든 상태를 Redis/DB로 외부화 → main·message 서버를 replica로 수평 확장.
- 자체 관리 Redis Sentinel → **AWS ElastiCache** 이전 *(이후 비용 문제로 자체 호스팅 회귀)*.
- **스케줄러 중복 실행 방어** — 여러 worker 인스턴스가 떠도 배치는 단 하나만 실행.

### 스케줄러 분산 락
```js
// SET NX EX = 생성(NX)과 만료(EX)를 원자적으로 동시 수행
const acquired = await redis.set(lock_key, 'locked', 'EX', 3600, 'NX');
if (acquired === 'OK') {
  // 락 획득 → 이 인스턴스만 배치 실행
} else {
  return; // 이미 다른 인스턴스가 실행 중 → 스킵 (중복 방지)
}
```
